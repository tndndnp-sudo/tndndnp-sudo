# Связь грязь — мессенджер-PWA

Адаптивный сайт-мессенджер, который можно добавить на главный экран Android и iPhone. Проект подготовлен для публикации как статический сайт на GitHub Pages; Supabase используется для реальных аккаунтов, чатов, запросов в друзья и файлов.

## Что уже есть

- регистрация и вход по логину и паролю;
- ник и личный код друга в формате `8291hg` (4 цифры + 2 латинские буквы);
- поиск по коду, запросы в друзья и личные чаты;
- текстовые сообщения, изображения, файлы и запись голосового сообщения;
- смена ника и аватара;
- адаптивный тёмный интерфейс и PWA-манифест;
- push-уведомления о новых сообщениях (после настройки Supabase Edge Function и VAPID-ключей);
- локальный демо-режим, чтобы попробовать интерфейс до подключения базы;
- офлайн-кэш контактов и последних сообщений, сохранение черновиков;
- очередь исходящих текстов, файлов и голосовых с повторной отправкой при восстановлении сети.

## Работа при плохой связи

Supabase-клиент уже включён локально в `vendor/`; после первого открытия с интернетом service worker сохраняет оболочку PWA, этот пакет, контакты и последние сообщения в браузере. Уже открытый ранее чат можно просматривать без сети. Черновик и исходящие текстовые сообщения, фото, файлы и голосовые сохраняются в локальную очередь IndexedDB; при появлении связи приложение попробует отправить их автоматически, а при ошибке оставит кнопку «повторить».

Офлайн не означает доставку: пока устройство не подключится к интернету, собеседник сообщения не получит. Синхронизация запускается, когда сайт снова открыт; гарантировать отправку из полностью закрытого приложения браузер не позволяет. Загруженные ранее вложения собеседника могут потребовать повторной загрузки из сети. Если очистить данные сайта, черновики и ещё не отправленная очередь удалятся. Самый первый запуск и вход в аккаунт нужно выполнить онлайн; последующие открытия смогут использовать сохранённую оболочку и локальную сессию.

Аудио- и видеозвонки в этот MVP не включены. Для них понадобится отдельный WebRTC/signalling слой и обычно STUN/TURN-серверы.

## Быстрый просмотр

Откройте сайт через локальный HTTP-сервер (не двойным кликом по HTML):

```bash
python3 -m http.server 4173
```

Затем откройте `http://localhost:4173`. Если `config.js` пустой, кнопка **«Попробовать демо»** запускает демонстрационный аккаунт. Демо-данные остаются в браузере и не синхронизируются между устройствами.

## Подключить настоящие аккаунты и чаты через Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. В SQL Editor выполните целиком файл `supabase-schema.sql`.
3. В Supabase Storage создайте два bucket:
   - `chat-files` — **private**;
   - `avatars` — **public**.
4. В настройках Authentication отключите **Confirm email** для этого MVP. Пользователи регистрируются только по логину, поэтому проект использует служебный адрес вида `логин@login.svyaz.invalid`. Это позволяет войти без почты, но пока **не будет сброса пароля по email**. Для публичного запуска стоит добавить подтверждённую почту/телефон или безопасную Edge Function для восстановления доступа. Если Supabase не принимает служебный домен как email, потребуется добавить реальную почту при регистрации или сделать отдельную Edge Function для входа по логину.
5. Откройте `Project Settings → API`. В `config.js` укажите Project URL и **anon/public key**:

```js
window.SVYAZ_CONFIG = {
  supabaseUrl: "https://ВАШ-ПРОЕКТ.supabase.co",
  supabaseAnonKey: "ВАШ-ПУБЛИЧНЫЙ_ANON_КЛЮЧ",
  vapidPublicKey: "ПУБЛИЧНЫЙ_VAPID_КЛЮЧ"
};
```

   **Не добавляйте `service_role` или secret key в сайт и GitHub.** Таблицы защищены RLS, а в браузере должен быть только публичный `anon` ключ.
6. Запустите сайт локально или опубликуйте каталог проекта на GitHub Pages. Деплой должен обслуживаться по HTTPS.

> После подключения Supabase используйте настоящие аккаунты только когда проверили настройки RLS и доступы Storage. В демо-режиме пароль не передаётся серверу и не должен совпадать с вашим настоящим паролем.

## Настроить push-уведомления о сообщениях

Код push-доставки находится в `supabase/functions/send-message-push/`. Таблица `push_subscriptions` и RPC для безопасной регистрации устройства входят в `supabase-schema.sql`; запускать эту схему нужно в Supabase SQL Editor. Для автоматического вызова Edge Function после каждого нового сообщения нужен `pg_net` и триггер из `supabase-push-trigger.sql`.

### 1. Создай VAPID-ключи и секрет вебхука

На своём компьютере выполни один раз:

```bash
npx web-push generate-vapid-keys
openssl rand -hex 32
```

Первой командой создай пару **Public Key / Private Key**, второй — случайный `PUSH_WEBHOOK_SECRET`. Сохрани private key и webhook secret в менеджере паролей. Не публикуй их и не добавляй в репозиторий. При смене VAPID-пары все устройства должны заново подписаться на push.

### 2. Задай серверные секреты и разверни Edge Function

Установи [Supabase CLI](https://supabase.com/docs/guides/cli), выполни `supabase login`, затем из папки проекта привяжи Supabase-проект:

```bash
supabase link --project-ref <project-ref>
```

Создай файл секретов **вне папки Git-репозитория** (например, `/tmp/svyaz-push.env`) со своими значениями и закрой доступ другим пользователям (`chmod 600 /tmp/svyaz-push.env`):

```dotenv
VAPID_PUBLIC_KEY=публичный_ключ
VAPID_PRIVATE_KEY=приватный_ключ
VAPID_SUBJECT=mailto:you@example.com
PUSH_SITE_URL=https://YOUR_GITHUB_USERNAME.github.io/YOUR_REPOSITORY/
PUSH_WEBHOOK_SECRET=тот_самый_случайный_hex_секрет
```

`PUSH_SITE_URL` — корневая HTTPS-ссылка опубликованного приложения; для GitHub Pages проекта сохрани завершающий `/`. Передай значения Supabase и удали локальный файл после настройки:

```bash
supabase secrets set --env-file /tmp/svyaz-push.env
supabase functions deploy send-message-push --no-verify-jwt
```

`SUPABASE_URL` и серверный ключ Edge Function предоставляет Supabase автоматически. Не добавляй `service_role`/secret key в `config.js` или GitHub. В `config.js` укажи только **публичный** `VAPID_PUBLIC_KEY` в `vapidPublicKey`.

### 3. Сохрани секрет вебхука в Vault и включи триггер

В Supabase Dashboard включи расширение `pg_net` в **Database → Extensions**. Затем один раз выполни в SQL Editor, подставив URL своего проекта и **тот же** случайный секрет, что в `PUSH_WEBHOOK_SECRET`:

```sql
select vault.create_secret(
  'https://<project-ref>.supabase.co/functions/v1/send-message-push',
  'push_function_url',
  'URL функции push-уведомлений'
);
select vault.create_secret(
  '<PUSH_WEBHOOK_SECRET>',
  'push_webhook_secret',
  'Секрет для вызова функции из триггера'
);
```

После этого выполни целиком `supabase-push-trigger.sql`. Он вызывает Edge Function асинхронно при `INSERT` нового сообщения. Ошибка push не отменяет и не блокирует сохранение сообщения. Секрет читается из Vault, а не хранится в SQL-файле.

### 4. Опубликуй сайт и включи уведомления на устройстве

1. Опубликуй обновлённую папку на GitHub Pages по HTTPS; значение `PUSH_SITE_URL` и `config.js` должны соответствовать этому адресу.
2. Войди в настоящий Supabase-аккаунт (демо-режим push не поддерживает) и нажми **«Включить уведомления»** в приложении. Разреши уведомления в системном запросе.
3. Для проверки добавь двух пользователей в друзья, включи push на устройстве получателя и отправь ему сообщение с другого аккаунта. При нажатии на уведомление приложение откроет чат с отправителем. В уведомлении показывается тип нового сообщения и имя отправителя, но не его текст.

На Android используй браузер с поддержкой Web Push (например, актуальный Chrome) и HTTPS. На iPhone/iPad открой сайт именно в Safari → **Поделиться → На экран Домой**, запусти установленное PWA и включи push из него. Push поддерживается в установленных веб-приложениях на iOS/iPadOS 16.4 и новее; в обычной вкладке Safari кнопка предложит инструкцию установки. Выход из аккаунта удаляет подписку этого устройства; после повторного входа включи push снова. Если разрешение ранее было запрещено, измени его в настройках браузера/iOS.

Настройка VAPID и Edge Function обязательна: без неё кнопка остаётся, но отправка уведомлений не работает. Подробности о механизме — в [Supabase Database Webhooks](https://supabase.com/docs/guides/database/webhooks) и [Supabase Edge Functions](https://supabase.com/docs/guides/functions).

## Опубликовать через GitHub Pages

1. Создайте GitHub-репозиторий и загрузите содержимое этой папки в корень репозитория.
2. В `Settings → Pages` выберите публикацию из ветки `main`, папка `/ (root)`.
3. Дождитесь HTTPS-ссылки и проверьте в Supabase `Authentication → URL Configuration`, что адрес сайта добавлен в `Site URL` / `Redirect URLs`.
4. Для установки откройте ссылку на телефоне. На Android используйте кнопку «Установить приложение» или меню браузера. На iPhone откройте сайт в Safari → «Поделиться» → «На экран Домой». iOS не показывает веб-сайтам универсальное системное окно установки, поэтому кнопка показывает инструкцию.

GitHub хранит исходный код и может раздавать сайт; **пользователи, сообщения и медиа хранятся в Supabase**, не в репозитории.
